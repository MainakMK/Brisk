# Brisk CDN — Phase 1 Build Specification

**Purpose of this file:** This is the complete context and build plan for **Phase 1** of the Brisk CDN project. It is written to be dropped directly into **Claude Code** so it has full context from day one. Read this entire file before writing any code. Build in the exact order given in Section 10.

> **Golden rule:** Brisk must run forever on its own code (Go + Nginx). No AI tool and no third‑party control service is part of the production runtime. Claude Code is the *builder*; the Brisk agent + Nginx are the *machine*.

---

## 1. Project background & vision (the big picture)

We are building **Brisk** — a self‑hosted Content Delivery Network (CDN), fully owned by us, similar in capability to Bunny / KeyCDN / CDN77. It is first for our own large private websites, and is designed so it can later be turned into a commercial product.

**What Brisk does:** caches and accelerates websites and video. Primary content types:
- **HLS video** (`.ts` / `.m4s` segments, up to ~5 MB each, 4K) — the main workload.
- **Static web assets** — HTML, CSS, JS, images (1 KB up to ~5 MB).

**Target scale (for context, not Phase 1):** 7–9 PoPs, ~3 servers each (~27 total), **10 Gbps** ports, **1–2 PB per day** total delivery. NVMe SSD + large RAM per node. Bare‑metal servers from providers like OVH (avoid Israel‑based). Cheap + unlimited bandwidth first.

**The proven pattern we follow:** every major buildable CDN runs **Nginx at the core** and wraps it with its own control + scripting layer:
- **Bunny** = Nginx + BunnyProxy (custom .NET proxy) + Lua + RabbitMQ + Deno.
- **KeyCDN** = tuned Nginx (Brotli, custom TCP stack, 100% SSD, anycast).
- **CDN77** = Nginx fork + OpenResty (Lua) + Wasmtime (Wasm plugins).

**Brisk copies this recipe:** **Nginx (cache) + Go agent (control) + Lua later.** We take only the proven, free pieces — no licensing cost, full ownership.

### System architecture (all phases, for orientation)
- **Edge nodes (PoPs)** — bare‑metal Linux running **Nginx + `brisk-agent`**. This is the data plane. **No Docker on edges** (Docker overhead is wasted; edges need raw performance).
- **Control plane (`brisk-control`)** — central Go API + database that manages zones, servers, rules, certs, purge. **Runs in Docker** (it is a management app, not latency‑critical) on our machine/server.
- **Dashboard (`brisk-dashboard`)** — web UI to manage everything. **Runs in Docker** alongside the control plane.
- **DNS / routing** — **Bunny DNS** (GeoDNS + smart/latency routing + anycast + health‑based auto‑failover) via its API.
- **Analytics** — **Postgres + TimescaleDB** (real‑time stats). ClickHouse only if we reach massive scale later.

### Non‑negotiable principles
1. **Data plane independent of control plane.** If the dashboard/control plane is down, edges keep serving from their last saved config. (Dashboard down ≠ CDN down.)
2. **Edges are bare‑metal; control plane/dashboard run in Docker.**
3. **Config delivery = pull + local persistence**, with a separate **instant channel** for purge (Phase 2). Edges save last‑known‑good config to disk.
4. **Lightweight everywhere** — one small static Go binary per edge; minimal dependencies.
5. **Brand everything as "Brisk"** in headers and naming.

## 3. Phase 1 scope — what is IN and what is OUT

**Phase 1 goal:** **one real edge node** that caches a real site over HTTPS, with Brisk branding and video support, fully installed and managed by the `brisk-agent`. Prove the core before building anything on top.

### IN (Phase 1)
1. `brisk-agent` Go program skeleton with all module stubs.
2. Nginx as the cache engine, **config generated by the agent**:
   - Disk (NVMe) cache + RAM key zone.
   - **Range requests** + **slice module** for HLS/video.
   - **Request coalescing** (`proxy_cache_lock`).
   - **Stale‑while‑revalidate** on origin errors.
   - **Branded headers**: `Server: Brisk`, `X-Brisk-Cache: HIT/MISS/BYPASS`, `X-Brisk-Edge`, `X-Brisk-Request-Id`.
   - **Brotli + Gzip** compression.
3. **TLS 1.3 + ECDSA**: self‑signed locally; Let's Encrypt on a real VPS.
4. **Edge tuning**: TCP BBR + file‑descriptor / connection tuning.
5. **Bootstrap installer**: one‑time SSH‑run script that installs Nginx + modules + tuning + the agent, and registers a **systemd** service.
6. **Local end‑to‑end test** in Docker/WSL2 against a test origin.

### OUT (Phase 1) — these come later, but leave hooks
- Dashboard UI, control‑plane API, multi‑server, Bunny DNS, analytics DB, network‑wide purge, Lua/edge scripting. (Phase 2+.)
- The agent must include **stub interfaces** for `config pull`, `purge`, `stats ship`, and `control-plane client` so Phase 2 plugs in without a rewrite.

## 4. Local development environment (Windows laptop)

We develop on Windows using a Linux sandbox. **Docker Desktop is already installed** (WSL2 backend present).

**Two valid options (pick one when starting):**
- **Docker Ubuntu container as the test "server"** (simplest with current setup): run an `ubuntu:24.04` container, install Nginx + the agent inside, map a port, test from Windows browser/curl.
- **WSL2 Ubuntu distro** (closest to production): `wsl --install -d Ubuntu`, run Claude Code + agent directly inside it.

**What can be fully tested locally:** Nginx caching (HIT/MISS), branded headers, range requests, slice/HLS behavior, Brotli/Gzip, the agent generating `nginx.conf` and reloading Nginx, the bootstrap script, and **self‑signed TLS**.

**What needs a real VPS (Phase 1 final check, ~$5–10/mo):**
- Real **Let's Encrypt** certificate (Let's Encrypt must reach the public domain — impossible on `localhost`; use self‑signed locally).
- Real public access + real latency.
- **TCP BBR's real effect** (and inside a Docker container the congestion‑control setting is governed by the *host* kernel, so set/validate BBR on the VPS, not in local Docker).

**Workflow:** build + test ~90% locally for free → rent one cheap VPS to validate the real‑world items → only then scale to many PoPs.

## 5. `brisk-agent` — architecture & file structure

The agent is **one small static Go binary** running as a systemd service on every edge. It is the "hands" of the (future) dashboard on each server. In Phase 1 it runs standalone from a local config file.

### Modules (responsibilities)
- **Bootstrap** — first‑time install: Nginx + modules, sysctl tuning, directories, systemd registration. Idempotent (safe to re‑run).
- **Config** — load zone/edge settings; **save last‑known‑good to disk**; generate `nginx.conf`; validate (`nginx -t`); graceful reload (`nginx -s reload`). (Phase 1: reads a local YAML. Phase 2: pulls from control plane, keeps local copy.)
- **TLS** — obtain + install certs and auto‑renew. Local = self‑signed; production = Let's Encrypt ECDSA via a Go ACME library.
- **Stats** — read `$upstream_cache_status` + `stub_status` (bandwidth, requests, HIT/MISS, CPU/RAM/disk). Phase 1: collect only. Phase 2: ship to control plane.
- **Purge** — delete cached objects. Phase 1: local purge (delete cache file). Phase 2: instant purge over a live channel.
- **Client** — secure, authenticated connection to the control plane. Phase 1: **stub interface** only.

### Suggested Go file layout
```
brisk-agent/
├── go.mod
├── main.go                     # entrypoint: parse flags, load config, start modules
├── config/
│   └── config.go               # load agent.yaml + zones; persist last-known-good
├── nginx/
│   ├── nginx.go                # render config, nginx -t, nginx -s reload
│   └── templates/
│       ├── nginx.conf.tmpl      # http{} block, cache zones, tuning
│       └── server.tmpl          # per-zone server{} block
├── tls/
│   └── tls.go                  # selfsigned (local) + ACME/Let's Encrypt (prod)
├── bootstrap/
│   └── bootstrap.go            # one-time install of nginx, modules, sysctl, systemd
├── stats/
│   └── stats.go                # read cache status + stub_status (ship = phase 2)
├── purge/
│   └── purge.go                # local cache purge (network purge = phase 2)
├── client/
│   └── client.go               # control-plane client INTERFACE (stub in phase 1)
└── deploy/
    └── brisk-agent.service     # systemd unit
```

### Agent config file (`/etc/brisk/agent.yaml`) — Phase 1 shape
```yaml
edge_id: "LOCAL-01"            # shows up in X-Brisk-Edge
mode: "local"                  # local | production
control_plane_url: ""          # empty in phase 1
cache_dir: "/var/cache/brisk"
cache_max_size: "200g"         # tune to disk size
zones:
  - domain: "test.example.com"
    origin: "http://origin:8000"
    tls: "selfsigned"          # selfsigned | letsencrypt
```

## 6. Nginx configuration spec (the exact caching behavior to generate)

The agent renders this from templates. Use it as the reference target. (`ORIGIN_HOST`, `TEST_DOMAIN`, `EDGE_ID` etc. are filled from `agent.yaml`.)

### Required Nginx modules
- **slice module** — for video range/segment caching (in official nginx.org packages; if building from source add `--with-http_slice_module`).
- **`ngx_brotli`** (dynamic) — build against the *matching* Nginx source version:
  ```bash
  ./configure --with-compat --add-dynamic-module=../ngx_brotli
  make modules
  cp objs/ngx_http_brotli_*.so /etc/nginx/modules/
  ```
- **`headers-more-nginx-module`** (dynamic) — needed to fully replace the `Server` header with `Brisk` (plain `add_header` cannot override the built‑in `Server` header).

### `nginx.conf` (target)
```nginx
load_module modules/ngx_http_brotli_filter_module.so;
load_module modules/ngx_http_brotli_static_module.so;
load_module modules/ngx_http_headers_more_filter_module.so;

worker_processes auto;
worker_rlimit_nofile 100000;
events { worker_connections 16384; multi_accept on; }

http {
    # ---- cache storage: NVMe disk + RAM key zone ----
    # keys_zone RAM holds the index; OS page cache keeps hot files in RAM automatically.
    proxy_cache_path /var/cache/brisk
        levels=1:2
        keys_zone=brisk_cache:512m     # ~4M cached objects
        max_size=200g                  # set to ~80% of NVMe
        inactive=7d
        use_temp_path=off;             # write straight into cache (less I/O)

    log_format brisk '$remote_addr $upstream_cache_status [$time_local] '
                     '"$request" $status $body_bytes_sent rt=$request_time';
    access_log /var/log/nginx/brisk.access.log brisk;

    sendfile on; tcp_nopush on; tcp_nodelay on;
    keepalive_timeout 65;
    server_tokens off;
    aio threads;                       # async file I/O for large video

    # ---- compression ----
    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml application/xml;
    brotli on; brotli_static on;
    brotli_types text/plain text/css application/javascript application/json image/svg+xml application/xml;

    # ---- request coalescing: one origin pull for simultaneous misses ----
    proxy_cache_lock on;
    proxy_cache_lock_age 5s;
    proxy_cache_lock_timeout 5s;

    # ---- resilience: serve stale on origin trouble + refresh in background ----
    proxy_cache_use_stale error timeout updating http_500 http_502 http_503 http_504;
    proxy_cache_background_update on;
    proxy_cache_revalidate on;

    upstream brisk_origin { server ORIGIN_HOST:ORIGIN_PORT; keepalive 32; }

    # http -> https redirect
    server { listen 80; server_name TEST_DOMAIN; return 301 https://$host$request_uri; }

    server {
        listen 443 ssl;
        http2 on;
        server_name TEST_DOMAIN;

        ssl_certificate     /etc/brisk/tls/TEST_DOMAIN/fullchain.pem;
        ssl_certificate_key /etc/brisk/tls/TEST_DOMAIN/privkey.pem;
        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_session_cache shared:BriskTLS:50m;
        ssl_session_timeout 1d;
        ssl_session_tickets on;
        ssl_stapling on; ssl_stapling_verify on;     # production cert only

        # ---- Brisk branding + debug headers ----
        more_set_headers "Server: Brisk";
        add_header X-Brisk-Cache    $upstream_cache_status always;
        add_header X-Brisk-Edge     "EDGE_ID" always;
        add_header X-Brisk-Request-Id $request_id always;
        add_header Strict-Transport-Security "max-age=31536000" always;

        # ---- HLS playlist: never cache (always fresh) ----
        location ~* \.(m3u8)$ {
            proxy_pass http://brisk_origin;
            proxy_cache off;
            more_set_headers "X-Brisk-Cache: BYPASS";
        }

        # ---- HLS segments + large video: slice + cache ----
        location ~* \.(ts|m4s|mp4)$ {
            slice 1m;
            proxy_cache brisk_cache;
            proxy_cache_key $host$uri$is_args$args$slice_range;
            proxy_set_header Range $slice_range;
            proxy_http_version 1.1;
            proxy_cache_valid 200 206 12h;
            proxy_pass http://brisk_origin;
        }

        # ---- everything else (html / css / js / images) ----
        location / {
            proxy_cache brisk_cache;
            proxy_cache_key $host$uri$is_args$args;
            proxy_cache_valid 200 301 302 1h;
            proxy_cache_valid 404 1m;
            proxy_set_header Host $host;
            proxy_pass http://brisk_origin;
        }
    }
}
```

**Notes / rules baked in above:**
- `.m3u8` playlists are **not cached** (live freshness). `.ts`/`.m4s`/`.mp4` are sliced into 1 MB pieces and cached — efficient for video range requests; the source file must be immutable while sliced.
- `proxy_cache_lock` = our request‑coalescing (Bunny‑style: a newly popular video = one origin pull, not thousands).
- `X-Brisk-Cache` maps directly to Nginx's `$upstream_cache_status` (HIT / MISS / EXPIRED / etc.).

## 7. TLS spec

- **Certificates:** ECDSA **P‑256** (≈⅓ the size of RSA, faster handshake). Protocols **TLS 1.3 + 1.2**. Enable **OCSP stapling**, **HSTS**, **session resumption/tickets**.
- **Production (real VPS):** Let's Encrypt. Preferred: the **agent obtains/renews certs natively in Go** using a Go ACME library (e.g. `go-acme/lego` or `caddyserver/certmagic`), writing `fullchain.pem` + `privkey.pem` to `/etc/brisk/tls/<domain>/` and reloading Nginx. (Fallback: `acme.sh --issue --keylength ec-256 --ocsp-must-staple`.) Auto‑renew on a timer well before the 90‑day expiry.
- **Local (Docker/WSL2):** generate a **self‑signed** ECDSA pair (Go `crypto/tls`/`crypto/x509`, or `mkcert` for a locally‑trusted CA). Selected via `tls: selfsigned` in `agent.yaml`. Disable `ssl_stapling` for self‑signed.

## 8. Edge tuning spec

Write to `/etc/sysctl.d/99-brisk.conf` and apply with `sysctl --system`:
```ini
net.core.default_qdisc        = fq
net.ipv4.tcp_congestion_control = bbr     # validate on real VPS (host kernel governs in Docker)
net.core.somaxconn            = 65535
net.ipv4.tcp_fastopen         = 3
fs.file-max                   = 2000000
net.ipv4.tcp_slow_start_after_idle = 0
```
Verify: `sysctl net.ipv4.tcp_congestion_control` → should print `bbr`.

Nginx side: `worker_processes auto`, high `worker_rlimit_nofile` + `worker_connections`, `sendfile/tcp_nopush/aio threads` for video. Brotli shrinks text assets ~15–25% vs Gzip → real bandwidth saving on a 10 Gbps line.

## 9. Bootstrap & systemd spec

`bootstrap.go` runs once (invoked over SSH by the control plane in production; run manually in Phase 1). It must be **idempotent**:
1. `apt update`; add official nginx.org repo; install Nginx (stable 1.30.x) + build deps.
2. Build/install dynamic modules: `ngx_brotli`, `headers-more-nginx-module` (against matching Nginx source). Ensure slice module present.
3. Apply `/etc/sysctl.d/99-brisk.conf` (BBR + tuning).
4. Create dirs: `/var/cache/brisk`, `/etc/brisk/tls`, `/var/log/nginx`.
5. Install `brisk-agent` binary to `/usr/local/bin/`.
6. Install + enable the systemd unit; start the agent.

`deploy/brisk-agent.service`:
```ini
[Unit]
Description=Brisk Edge Agent
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/brisk-agent --config /etc/brisk/agent.yaml
Restart=always
RestartSec=3
LimitNOFILE=1000000

[Install]
WantedBy=multi-user.target
```

## 10. Build order (do it in THIS sequence)

1. **Repo skeleton** — `go mod init`, file layout from Section 5, `config.go` loading `agent.yaml`.
2. **`nginx.go` + base templates** — generate a working `nginx.conf` for plain HTTP caching of the test origin; `nginx -t`; `nginx -s reload`. **Test: cache MISS then HIT.**
3. **Video + coalescing + headers** — add slice/HLS locations, `proxy_cache_lock`, and the `X-Brisk-*` / `Server: Brisk` headers (build `headers-more` module). **Test: range request returns 206, `.m3u8` shows BYPASS.**
4. **`tls.go` (local self‑signed)** — switch the server to 443 with a self‑signed ECDSA cert. **Test: HTTPS loads, TLS 1.3.**
5. **Edge tuning + Brotli** — sysctl file + Brotli module + types. **Test: `Content-Encoding: br` on text assets.**
6. **`bootstrap.go` + systemd** — one‑command fresh‑server install; agent runs as a service. **Test: reboot container → agent + Nginx come back up.**
7. **End‑to‑end local test** — full run in Docker/WSL2 against the test origin (Section 11).
8. *(After local pass)* — deploy to one cheap VPS, switch `tls: letsencrypt`, validate real cert + BBR + public access.

Work **one file/step at a time**; confirm each test passes before moving on.

## 11. Phase 1 acceptance tests (definition of done)

Set up a simple **test origin** (any static file server, or a sample HLS stream) and point `test.example.com` at the edge (hosts file locally). Then verify:

```bash
# 1) Caching: first MISS, second HIT
curl -ksI https://test.example.com/style.css | grep -i x-brisk-cache   # MISS
curl -ksI https://test.example.com/style.css | grep -i x-brisk-cache   # HIT

# 2) Brisk branding
curl -ksI https://test.example.com/ | grep -iE 'server:|x-brisk-'      # Server: Brisk + X-Brisk-* present

# 3) Brotli
curl -ksI -H 'Accept-Encoding: br' https://test.example.com/app.js | grep -i content-encoding   # br

# 4) Range / video
curl -ksI -H 'Range: bytes=0-1048575' https://test.example.com/video/seg1.ts | grep -i '206'      # 206 Partial

# 5) Playlist not cached
curl -ksI https://test.example.com/video/index.m3u8 | grep -i x-brisk-cache   # BYPASS

# 6) TLS version
curl -ksI --tlsv1.3 https://test.example.com/ | head -1                 # 200/301 over TLS 1.3

# 7) Request coalescing (concurrent misses -> ~1 origin hit) — check origin logs under: 
#    seq 50 | xargs -P50 -I{} curl -ks https://test.example.com/big.mp4 -o /dev/null
```
Phase 1 is **done** when all of the above pass locally, and the same passes on one real VPS with a real Let's Encrypt cert.

## 13. Coding standards & constraints

- **Go latest stable (1.26.x)**, single **static binary**, minimal external dependencies.
- **Idempotent bootstrap** (safe to re‑run; check‑before‑install).
- **Never reload Nginx with a bad config** — always `nginx -t` first; only `nginx -s reload` (graceful, zero dropped connections) on success; keep the previous good config to roll back.
- **No Docker on edge** runtime. Docker is only the local test sandbox and the (separate) control‑plane/dashboard host.
- **Lightweight**: low idle CPU/RAM; the box's resources are for caching.
- **Secure defaults**: agent runs locally in Phase 1; Phase 2 adds authenticated control‑plane comms. Origin lockdown (mTLS / secret pull header) is a later security‑phase task — leave a note, don't expose origin IP in production.
- **Brand consistently**: binary `brisk-agent`, paths under `/etc/brisk` and `/var/cache/brisk`, headers `X-Brisk-*`, `Server: Brisk`.

## 14. Quick reference — key numbers & facts

- **1 Gbps ≈ 125 MB/s** hard ceiling; network is the primary bottleneck (not CPU/RAM/disk). RPS by size on 1 Gbps: ~12,500 @ 10 KB, ~1,250 @ 100 KB, ~25 @ 5 MB.
- **10 Gbps is the #1 upgrade** when a PoP saturates. Target scale (1–2 PB/day) needs ~93–185 Gbps sustained across the network → 10 Gbps ports per node.
- **NVMe SSD required at 10 Gbps** (disk must feed ~1,250 MB/s; only NVMe ≈ 3,000+ MB/s qualifies). Use datacenter‑grade NVMe (write endurance). RAM = automatic hot tier via OS page cache; aim 128 GB+.
- **TLS:** Xeon‑class CPU does ~2–3k RSA handshakes/s but **10,000+/s with ECDSA P‑256** → always ECDSA. Session resumption ≈ zero CPU.
- **ECDSA cert** ≈ ⅓ the size of RSA; **TLS 1.3** = 1‑RTT handshake (+0‑RTT resume).
- **DNS (Phase 2):** set TTL ~3600 to cut query bills ~50%; budget ~$20–40/mo on Bunny DNS.
- **Nginx open‑source purge:** there is no built‑in `proxy_cache_purge` directive (that's NGINX Plus). Brisk purges by deleting the cache file (or via the third‑party `ngx_cache_purge` module). The agent owns purge.
