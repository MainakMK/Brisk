Brisk is a CDN you fully own — like Bunny / KeyCDN / Cloudflare, but built from free, proven pieces (Nginx for caching, a small Go agent on each edge, and a Go control plane with a React dashboard). It serves HLS video + static assets fast from servers near each visitor.

1The big picture (30,000 ft)

Everything in Brisk is one of five things: visitors, the edges that serve them, the control plane that manages the edges, the dashboard a human uses, and the external services (Bunny DNS, your origins). Here is how they all connect.

Figure 1 — the whole system. Solid = live traffic / management; dashed = control signals.
The golden rule that shapes everything: the data plane is independent of the control plane. If the brain (control plane / dashboard) is down, the edges keep serving from their last saved config. Dashboard down ≠ CDN down.

2The two planes (the core idea)

Data plane — the edges

Bare-metal servers around the world, each running Nginx (does the actual caching + serving) and a small brisk-agent (the Go program that configures Nginx and talks to the brain). This is what your visitors hit. Built to be lightweight: one tiny static binary per edge, all the box's resources go to caching.

code: brisk-agent/ · runs on: each PoP (NY, FRA, BLR…)

Control plane — the brain

A Go API (brisk-control) + Postgres/TimescaleDB + NATS + the React dashboard, all in Docker on one host. It stores all settings, decides DNS routing, watches edge health, drives rollouts, issues TLS, and fans out purges. Edges pull from it; it never needs to be public-facing for traffic.

code: brisk-control/ + brisk-dashboard/ · runs on: one server

4Inside an edge — the brisk-agent

The agent is the Go program on every PoP. It owns one job: keep Nginx configured correctly and stay in touch with the brain. It never serves visitor traffic itself — Nginx does that. The agent is a set of small packages, each with one responsibility, orchestrated by main.go's loops.

Figure 3 — the agent's packages and how they drive Nginx + talk to the brain.
Package (brisk-agent/)What it does
main.goThe conductor. Boot self-check, then runs the background loops (config poll, heartbeat, stats, purge, self-update, TLS renew).
config/Loads agent.yaml (local truth) and overlays the zones pulled from the control plane (ControlPlaneSource), caching the last good config so the edge survives the brain being down.
client/The authenticated link to the control plane: heartbeat, PullConfig (ETag-conditional), stats ship, and signed-release fetch/download.
nginx/Renders the nginx.conf + per-zone vhosts from templates, validates with nginx -t, reloads only on success, rolls back on failure.
tls/Two-phase certs: write a self-signed placeholder so Nginx can start, then obtain/renew the real Let's Encrypt cert; OCSP stapling, renewal margins.
waf/OWASP Coraza engine + CRS v4 as an auth_request sub-service; per-zone custom rules, country rules, security-event buffer.
stats/Scrapes Nginx stub_status + CPU/RAM/bandwidth, buffers samples (bounded, drop-oldest) and ships them to the control plane.
logship/Tails the structured JSON access log and ships bounded batches to the control plane (feeds the Logs page + analytics).
purge/Subscribes to the NATS purge subject and deletes the matching cache files (open-source Nginx has no purge directive).
selfupdate/The over-the-air updater: verify ed25519 signature → atomic binary swap → restart → self-check → auto-rollback. The signature (not the channel) is the trust anchor.
bootstrap/Idempotent first-run setup of the box: build the Nginx modules, geoip2, Lua, systemd unit, kernel BBR, directories, placeholder config.

5Inside the brain — the brisk-control plane

The control plane is a Go API (chi router) on top of Postgres/TimescaleDB, plus a handful of background loops that keep the world in sync. Requests come from two kinds of caller: the edges (agent-token auth) and the dashboard (human/session or admin-token auth).

A React + TypeScript single-page app (Vite, Tailwind, TanStack Query). It is a thin client: it never talks to edges or the database directly — every screen is just pages → hooks → the api client → the control plane.

7Key data flows (how the important things actually happen)

7.1 Config pull (how an edge learns its settings)

agent configPollLoop → GET /api/v1/agent/config (If-None-Match: ETag) → control compares config_version → 304 Not Modified (nothing changed) or 200 + new config → agent overlays zones, renders nginx, nginx -t, reload. The last good config is cached on disk so the edge survives the brain being offline.

7.2 Heartbeat + stats + logs (how the brain sees the fleet)

every 30s: POST /agent/heartbeat (online + nginx/agent/OS/kernel/Go versions) → servers table. Continuously: stats ship CPU/RAM/bandwidth + logship ship JSON access logs → TimescaleDB hypertables → the Analytics + Logs pages.

7.3 Purge (instant, network-wide)

dashboard/API POST /purge → control records a purge job → NATS publisher fans a message to every edge's subject → each edge's purge consumer deletes the matching cache files. Survives the control plane restarting (JetStream is durable).

7.4 DNS routing + failover (how visitors reach the nearest healthy edge)

health checker probes /healthz (5s) → if an edge fails, the reconciler diffs desired vs. Bunny and removes it from rotation; the syncer writes Smart-Records to Bunny. A second layer (Bunny's own native ping monitor, gated) is a backstop if the control plane is down. An all-down guard prevents pulling the last PoP.

7.5 TLS (how certs appear, automatically)

agent writes a self-signed placeholder so Nginx can boot → the control plane's acme manager issues the real wildcard cert (lego, Bunny DNS-01) and fans it to edges; customdomains does the same per tenant. Renewals run on a 12h check.

7.6 Agent self-update (ship new agent code safely)

CI (or you via briskctl release push) builds + ed25519-signs the agent → uploads to the release store. A human clicks Deploy → the rollout engine opens one PoP's wave → that edge's releaseLoop downloads + verifies the signature → swaps its own binary → restarts → self-checks → soaks → engine advances to the next PoP. A bad signature is refused; an unhealthy update auto-rolls-back. See Brisk_Agent_Rollout_Process.html.

10Stack & the rules that shape it

Tech stack

  • OS: Ubuntu 24.04 LTS (edges)
  • Cache: Nginx stable 1.30.x (nginx.org)
  • Language: Go 1.26 — one static binary per side
  • TLS: Let's Encrypt ECDSA P-256, TLS 1.3+1.2, OCSP, HSTS
  • Compression: Brotli (ngx_brotli) + gzip
  • Video: Nginx slice module (1 MB), request coalescing
  • Edge programmability: lua-nginx-module (gated rules)
  • Security: Coraza WAF + OWASP CRS v4
  • Kernel: TCP BBR (fq+bbr)
  • Control DB: Postgres 17 + TimescaleDB
  • Messaging: NATS JetStream (purge)
  • Routing: Bunny geo-DNS (Smart-Records)
  • Dashboard: React + TS + Vite + Tailwind + TanStack Query

Golden rules (non-negotiable)

  • Data plane independent of control plane. Dashboard down ≠ CDN down.
  • Never reload Nginx with a bad config. Always nginx -t first; keep the previous good config to roll back.
  • Edges = bare-metal, no Docker. Docker is only for local testing + the control plane.
  • Idempotent bootstrap — safe to re-run.
  • Lightweight everywhere — one small binary per edge.
  • New features ship gated + OFF — the live fleet stays byte-identical until a feature is deliberately enabled per-zone/per-edge.
  • Byte-identical rollouts — every agent deploy proves sha256(nginx.conf) is unchanged before/after.
  • Never drop a live hostname with zero in-rotation PoPs.
  • Origin IP never exposed — secret pull header / shield in front.

11Glossary (plain English)

TermMeans
Edge / PoPA server near visitors that caches + serves your content. ("Point of Presence".)
Data planeThe edges — the part that serves real traffic.
Control plane / brainThe API + DB + dashboard that manage the edges (but serve no visitor traffic).
Agent (brisk-agent)The Go program on each edge that configures Nginx + talks to the brain.
ZoneOne site/hostname Brisk serves (its origin, cache rules, TLS, WAF…).
OriginYour source server — where Brisk fetches content on a cache MISS.
ShieldA chosen edge that sits in front of the origin so fewer edges hit it directly.
HeartbeatA periodic "I'm alive + here's my status" message from an edge to the brain.
PurgeForce-delete cached copies so the next request re-fetches fresh content.
Smart-RecordA Bunny geo-DNS record that returns the nearest healthy edge per visitor.
ETag / 304"Nothing changed" — the edge asks for config and the brain replies 304 if it's already current (saves bandwidth).
Gated / off by defaultCode is present but disabled until you flip a switch — so it can't surprise the live fleet.
Byte-identicalThe rendered nginx.conf is exactly the same before and after a change — proof nothing about serving changed.
Self-updateThe agent updating its own binary over the air, verified by your signature, with auto-rollback.

Appendix G · The rendered nginx.conf + every request body (the last detail)

G.1 — What the agent actually writes to an edge. brisk-agent renders two templates: nginx.conf.tmpl (the global http block) and server.tmpl (one server-block pair per zone). Gated features render only when enabled for that zone/edge — which is why an untouched fleet stays byte-identical. Structure:

/etc/nginx/nginx.conf        (generated — DO NOT EDIT BY HAND)
├─ load_module …             ndk · lua · headers-more · brotli×2 · geoip2   (only those installed)
├─ worker_processes auto · worker_rlimit_nofile 200000 · user www-data     (owns the cache dir)
├─ events { worker_connections 32768 }
└─ http {
   ├─ proxy_cache_path /var/cache/brisk    NVMe disk + RAM key zone   ← purge = agent DELETES files
   ├─ init_by_lua_file init.lua            (only when the Lua module is present)
   ├─ lua_shared_dict brisk_rl 10m         per-IP 401/403 counter (errors-only rate limit)
   ├─ geoip2 → $brisk_country              (only when geoip2 + GeoLite2 DB present; else "-")
   ├─ log_format brisk  +  JSON → brisk.requests.log   ← logship tails this → control plane
   ├─ brotli + gzip · TLS 1.3/1.2 ECDSA · OCSP · HSTS · slice 1m · proxy_cache_lock (coalescing)
   ├─ default_server { ssl_reject_handshake }          ← unknown SNI rejected (no cross-zone leak)
   └─ « per-zone server blocks »           one pair per zone, from server.tmpl ↓

zone <cdn_hostname> :
├─ server :80
│  ├─ location ^~ /.well-known/acme-challenge/   → proxy to control plane (custom-domain CA answer)
│  ├─ location = /healthz                        → 200 "ok"   (cheap HTTP liveness probe)
│  └─ location /                                 → 301 https
└─ server :443 ssl http2
   ├─ resolver + $brisk_origin                   resolve origin at request-time, force IPv4
   ├─ ssl_certificate (covering cert, longest-suffix match) · OCSP stapling
   ├─ more_set_headers  Server: Brisk · X-Brisk-Edge · X-Brisk-Request-Id   (applies on EVERY status)
   ├─ [gated] if ($request_method = POST) return 405;          ← block_post
   ├─ [gated] if ($uri ~ "/$") return 403;                     ← block_root_path
   ├─ [gated] valid_referers … + "hotlinkguard" 403            ← hotlink (content locations only)
   ├─ [gated] limit_conn / limit_req → 503 / 429               ← edge_protect (per-IP)
   ├─ [gated] rewrite_by_lua + header_filter_by_lua            ← cache rules + header transforms
   ├─ [gated] access_by_lua (block IPs over the 401/403 limit) ← errors-only rate limit
   ├─ [gated] auth_request /waf  (fail-open | fail-closed)     ← Coraza WAF + CRS
   ├─ [gated] deny <ip/cidr>;  on content locations            ← blocked-ips denylist
   ├─ location = /healthz            → 200   (TLS probe; NEVER WAF/hotlink-guarded)
   ├─ location ~ \.m3u8$             → proxy, NEVER cache  (X-Brisk-Cache: BYPASS)
   ├─ location ~ \.(ts|m4s|mp4)$     → slice 1m · proxy_cache · key incl $slice_range · validate 200|206
   ├─ location / (static + html)     → proxy_cache · proxy_cache_bypass $http_x_brisk_lua_nocache
   ├─ upstream = shield PoP (if shielded) + @brisk_origin_fallback   ELSE → origin directly
   ├─ [gated] @brisk_follow_redirect (chase one origin 3xx)    ← origin_follow_redirects
   ├─ [gated] error_page 502/504 → custom branded HTML         ← error_5xx_html
   └─ [gated] proxy_set_header <secret>  to the origin         ← origin lockdown (origin_pull_secret)

Renderer: brisk-agent/nginx/nginx.go (+ cache.go for the cache-settings block). Every reload is guarded by nginx -t; on failure the agent keeps the previous good config.
